Case study

Level UP

Synth Riders' player experience and progression system: levels, achievements and challenges that reward long-term play. It launched in March 2026 on Meta Quest and PC VR, and the studio called it its largest feature update to date. I designed and built it as its primary developer.

What players get

A reason to come back, and a place to see it

Before Level UP the game kept scores but not a player's journey. Now every song counts toward something, and the progress is visible in the menus, after each song and to other players.

100levels, with a new nameplate badge every five
93achievements, in tiered series, collections and one-offs
3kinds of challenge: intro, daily and weekly, with rewards to claim
2platforms at launch: Meta Quest and PC VR

In the menus

  • The player panel. Profile, level, badge and lifetime stats in one place. The level also shows on the nameplate in single-player and multiplayer.
  • Achievements. Filterable, with animated progress and medals in three ranks.
  • Challenges. Intro challenges that guide a new player, then daily and weekly ones. Rewards are claimed one by one or all at once, in song selection and in the multiplayer lobby.

After every song

  • The post-game panel. What the song just earned: XP, level-ups, and progress on achievements and challenges.
  • Moments. An animated level-up on the nameplate, and toasts when something unlocks.
  • Every way to play counts. Regular songs, retries, non-stop runs, challenges and experiences all report in.
How it works

The server decides, the client shows

The client reports what happened in a song. The server answers with the player's new state, their progress and any rewards. The client never decides XP, levels or unlocks on its own.

Client and server

  • Contract first. I wrote and maintained the API document the backend was built against, and an in-editor tool to test the API.
  • A mock backend behind the same interface, so the client could be built and tested before the server existed.
  • Sign-in through the player's Steam or Meta account.
  • Text served remotely. Achievement and challenge text comes from the server in each language, so it can change without a game update.

Inside the game

  • Session tracking across scenes. A tracker follows a song from selection through gameplay to the score screen, and survives the scene reloads of a retry.
  • Works offline. Server data is cached locally and encrypted. Panels show offline and waiting states, and the client reconnects on its own.
  • A cache that knows when it is stale. It is invalidated by age, by game version and by server.
  • A session cache so switching tabs does not refetch what has not changed.
The hard parts

What it took to make it feel right

Performance

  • A panel that froze when opened. The achievements list built every entry at once. I moved it onto a recycling list, a component I had written earlier for the song list and generalized for this, so only the visible rows exist.
  • Nothing may allocate during a song. A pass on the hit-feedback path removed the memory allocated on every note: tweens built once and reused, timers in place of coroutines, number text cached.
  • An audit tool for the interface. I wrote an editor tool that scans prefabs for costly settings, then cleaned up the thirteen prefabs of the new panels.

Correctness

  • A race at startup. Sign-in could start initialization twice. A guard set before the first wait closed it.
  • A stat that was always zero. Rails cleared were derived from a formula that cancelled itself out, so rail achievements could not progress. Fixed where the number is produced.
  • Songs with the same name. Two songs sharing a title were reported as one. Matching on title and artist fixed XP and challenge tracking for them.
  • A level-up that could freeze the game. The animation is now cancellable.
